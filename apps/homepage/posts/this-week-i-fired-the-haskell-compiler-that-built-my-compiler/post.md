# This Week I Fired the Haskell Compiler That Built My Compiler

*Also: a Zelda camera in a terminal, an AI that learned to shut up, and a leaked webhook.*

Most weeks I can pick a headline project and let the others be footnotes. Not this one. One repo alone ate what feels like a full-time job for seven straight days, and I still want to talk about the SSH desktop, the AI phone-call app, and the resume site's brush with a leaked secret. So let's do the big one first, then the rest.

## Alpha: I stopped needing the language I wrote it in

Alpha is my from-scratch compiler and GPU runtime project — a language and toolchain built to compile model training code straight down to machine instructions, with no PyTorch, no CUDA runtime, nothing borrowed. I've written about pieces of this before. This week the project crossed a line that's worth explaining properly: I retired the last of the Haskell.

Here's the shape of it. Alpha, the language, was originally implemented *in* Haskell — a bootstrap compiler written in someone else's battle-tested tooling so I could get a real language off the ground without also inventing a parser-and-type-checker framework from nothing. That's completely normal; it's how most languages start (Rust's original compiler was OCaml, TypeScript was authored in itself only after enough of TypeScript existed to write TypeScript). The end goal, though, was always self-hosting: get Alpha good enough that Alpha's own runtime, training pipeline, and GPU driver code could be written *in Alpha*, and the Haskell scaffolding could be thrown away.

This week that happened. Dozens of commits, each one narrow and boring on its own — "retire Haskell native operand planner," "retire Haskell checkpoint and dispatch roots," "retire Haskell RNG mathematics" — added up to deleting the entire Haskell-authored training and runtime stack and replacing it, module by module, with Alpha-native code that Alpha itself compiles. The interesting engineering isn't in any single deletion; it's in the discipline of doing it as a long chain of small, verified swaps instead of one big rewrite. Every retirement commit exists because the Alpha-native replacement already type-checked and ran before the old Haskell file was deleted. That's the only way to do a self-hosting transition without a multi-week period where nothing works.

The other big thread is talking to the GPU without CUDA. NVIDIA's actual driver interface — the thing CUDA sits on top of — is a set of ioctl calls to a kernel module (the "RM" and "UVM" layers). Nobody publishes a clean spec for this; you reconstruct it by reading driver source and matching bit layouts. This week's commits show that grind directly: deriving "canonical GPU authority" structures, building a native NVIDIA device protocol from scratch, validating version replies, allocating memory-mapped launch bindings, and eventually getting a real ELF binary built by Alpha to run on an actual RTX 3090 and report back a status instead of crashing. That last part matters more than it sounds — "compiles" and "the GPU driver accepts your binary and replies coherently" are very different bars to clear, and the commit history has a visible moment where a training run got killed by something *outside* the process and the fix was learning to detach cleanly from that signal instead of treating it as a crash.

The part I actually want to teach, though, is a performance bug that's a great cautionary tale for anyone writing a type checker, interpreter, or any tree-walking system: **using unary numbers for indices will always come back to bite you.** Alpha's type checker represents natural numbers the way formal logic textbooks do — as a successor chain, `Zero`, `Succ Zero`, `Succ (Succ Zero)`, and so on — because it's the simplest thing to reason about and prove correct. The catch is that every operation on a unary number costs time proportional to its size: comparing two numbers, or worse, dividing one by another, does work linear (or worse) in the value, not in the number of digits. That's fine for small numbers. It is not fine when that same representation gets reused for variable-lookup indices in the checker's context — the thing that answers "what's the type of variable #148 in this scope" — because now every single variable reference costs time proportional to how deep in scope it is. Profile the checker and you find exactly what got found here: one function, doing index lookups, eating nearly a fifth of all runtime across 148 million calls. The fix wasn't a clever algorithm, it was recognizing the representation itself was the bug and swapping to something with actual random access. A separate but related fix — annotating definitions so the checker doesn't have to re-infer their types from scratch every time they're used — reportedly cut one specific compile wall from minutes to under a second. Type annotations aren't just for humans; they're a cache.

If you read the raw commit log for this repo it looks unhinged — hundreds of tiny, oddly-specific messages like "the fifth shape was one closer one line early, not N closers at once." That's from a multi-day hunt inside the project's own ELF linker/auditor, where a syntax-repair tool kept guessing wrong about where a closing delimiter belonged in reformatted source files, and each commit is a step in narrowing down *why*. What's actually going on underneath the noise is a strict, almost scientific discipline: every claim of progress gets a numbered checkpoint ("R3 MET," "R5 MET") that only gets marked done once there's real evidence, and there are multiple commits that exist purely to say "I was wrong, here's the correction" — a hypothesis about why SHA-256 wouldn't compile getting refuted, an "unrolling explains it" theory getting killed by an experiment, an over-claimed milestone getting walked back the next day. There's also a moment where an automated batch tool rewrote 177 files and the whole thing got reverted because it couldn't be trusted — which is exactly the right call, and a good reminder that "the tool touched a lot of files successfully" is not the same as "the tool is right."

By the end of the week the compiler could take a full ~380-module closure of its own codebase, parse it, type-check it, and lower it to machine code in about a minute, and had run real proving workloads — including a full SHA-256 implementation — through both a slow reference path and a fast "direct" compilation path that used to only support toy-sized data shapes (two-field records, two-branch choices) and now handles arbitrary ones. Whether this ever trains a real model on that RTX 3090 is still an open question. But "the compiler I wrote compiles itself and talks to my own GPU driver" is a real result, not a vibe.

## tellus: Zelda camera, in your terminal, over SSH

tellus is my terminal 3D engine — real color, real geometry, streamed to whatever terminal you're sitting in over SSH, no client install. This week it got an actual game-feel upgrade: a follow camera with Z-targeting and roll. If you played Ocarina of Time, Z-targeting is that mechanic where you lock onto an enemy and the camera orbits around the midpoint between you and them instead of you having to aim the camera yourself — it's a cheap trick that makes melee combat in a 3D space feel controllable instead of chaotic, because the game is doing your camera work for you. Getting that to feel right over an SSH terminal, where you're rendering full 3D scenes as colored text cells at whatever frame rate the connection allows, is a genuinely different problem than doing it in a normal game engine.

The other big addition is what the commits call "the storybook city" — a full open world built from about 400 harvested 3D models stitched together into one explorable space, alongside a boat-era model fidelity fix that makes sure the original geometry survives at the closest level of detail instead of getting simplified away. Building a coherent-looking world out of hundreds of unrelated model assets is mostly a curation and normalization problem: getting scale, orientation, and materials consistent enough across models that were never designed to sit next to each other.

## ham: giving AI agents a shared, provable memory

ham is a shared PostgreSQL-backed memory system that multiple AI agents can read and write via MCP (Model Context Protocol — the emerging standard for how an AI agent talks to external tools and data sources). The pitch is simple: agents working on the same problem shouldn't each carry their own private, disconnected notebook.

This week's real work was a roadmap feature — a shared, revisioned, zoomable timeline that agents can read from and publish to — and, more interestingly, hardening its validator. A shared graph that any agent can write to is an invitation for corrupted data: NaN or Infinity values sneaking into numeric fields, or worse, dependency cycles where item A contains item B which contains item A, which would make anything that tries to walk the graph (to render it, to compute a critical path, to size a timeline) loop forever. The fix was rejecting both classes outright at write time rather than trying to defend every downstream reader against garbage input. That's the right instinct for shared mutable state written by things you didn't personally write the code for: validate hard at the boundary, because you cannot audit every future writer.

## sshomarchy: making a fun hack survive being public

sshomarchy streams one shared Linux desktop into every SSH session that connects to it — everyone who logs in is looking at, and can nudge, the same live desktop. It's a genuinely fun idea, and this week's work was almost entirely about the unglamorous cost of taking something like that from "cool demo" to "thing strangers can hit without me getting paged."

That meant: recovering client leases cleanly after a gateway crash, resyncing every connected viewer after the shared session restarts instead of leaving them stuck on a frozen frame, adapting frame rate and bandwidth to each viewer instead of pushing one fixed rate to everyone, standardizing logs so an incident can actually be traced back to a cause, and — the one I like most — a twelve-hour soak test gate with deterministic reboots, meaning the service now has to prove it survives half a day of continuous operation and a scripted restart before that's considered "done." There's also a real security move buried in there: constraining raw SSH access once the public-facing viewer path went live, so the thing anonymous visitors connect to isn't the same trust boundary as the thing the operator uses to manage the box.

## blah.dev: teaching a voice AI to shut up on cue

blah.dev is a video-calling app where AI agents can join as actual participants — not a bot bolted onto the side, but something that can be invited into a room, see and hear what's happening, speak, and (as of this week) draw. The resident agent is called omega, and the interesting problem this week was less "can it talk" and more "can it tell when *not* to."

A voice-first agent listening on an open mic has to solve a genuinely hard problem: knowing when it's actually being addressed versus just present in the background, and knowing when its own turn is over. This week's commits describe fixing the agent mishearing the word "stop" as something else entirely, keeping Whisper's non-speech annotations (the bracketed sound-effect tags it emits for things like music or laughter) out of the actual conversation transcript, and giving omega logic to decide for itself when to speak, with a manual mute the room can invoke if it doesn't. There's also a nice, boring-but-real latency fix: turning off word-level timestamps in the Whisper transcription request, because most of the transcription cost comes from Whisper trying to align each individual word to an exact time offset — if you only need the text, skipping that alignment step gets you a text response measurably faster, and the commit describes this bringing transcription latency down by roughly half. That's the kind of fix that's invisible in a demo and directly determines whether a voice AI feels like it's listening or like it's on a satellite delay.

On the infrastructure side, meet — the calling app — moved into the same monorepo as the rest of blah.dev, now sharing auth and a database instead of running as its own island, and agents gained persistent images and a real invite flow so an agent can be pulled into a call mid-conversation instead of only being addable at room creation.

## jsonresume.org: the boring security fixes that matter most

Two changes here, both worth calling out specifically because they're the unglamorous kind that actually prevent incidents: a leaked Discord webhook URL got pulled out of the repo, and the API now requires a signed-in session before it will issue an API key. Webhook URLs are bearer credentials — anyone who has the URL can post to that channel, no other auth required — so an accidentally committed one is a live exposure the moment it's pushed, not just a style nit. Same logic on the API key path: an endpoint that mints credentials without checking who's asking is a vending machine for anyone who finds it. Neither fix is exciting to write about. Both are exactly the kind of thing that's much cheaper to catch in review than to explain in a postmortem.
