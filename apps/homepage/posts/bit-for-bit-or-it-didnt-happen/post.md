# Bit-for-Bit or It Didn't Happen

*A GPU driver I wrote from scratch finally ran a training step. A voice agent learned to shut up. A GPT clone trained in a language with no threads in it.*

Five repos this week, and I'm going to spend most of my words on the one that finally paid off a bet I've been making for months: that you can write a GPU training stack without borrowing a single line of NVIDIA's software. Then I'll get into the agent platform I'm building, the voice AI that's slowly learning manners, and a language experiment that trains a tiny GPT without ever calling `thread.spawn`.

## Alpha: the compiler talked to a GPU and the numbers matched

Alpha is my from-scratch language and compiler for training neural nets — no PyTorch, no CUDA runtime, no borrowed math libraries. Everything from the type checker down to the bytes that get handed to the GPU driver is code I own. This week the "talks to a real GPU" side of the project, which I've been calling coppelius internally, hit the milestone that actually matters: a fixed hundred-step training run on a real RTX 3070, produced by code the compiler generated, not by anything hand-written in C or CUDA.

Getting there meant working through a long ladder of individual kernels — LayerNorm, GELU, softmax, attention head splitting and merging, cross-entropy, AdamW, embedding gather and scatter, transposes — and proving each one correct before composing them. "Correct" here doesn't mean "looks reasonable" or "doesn't crash." It means running the same computation two ways — the fast GPU kernel and a slow, obviously-correct reference implementation — and diffing the output down to the bit, or in the handful of cases where floating point makes exact equality unreasonable, to an explicitly declared tolerance like five parts in a hundred million. This is the only sane way to build a kernel library you can trust. If you only test the whole pipeline end to end, a wrong answer tells you nothing about where the bug lives — the error could be in any of a dozen kernels, and float rounding will happily hide a real bug behind a plausible-looking loss curve. Testing kernel-by-kernel against ground truth means when something's wrong, you know exactly which forty lines to stare at.

The GPU side of this is also just genuinely obscure work. NVIDIA doesn't publish a spec for how CUDA actually talks to the kernel driver underneath it — you reconstruct the wire format by reading driver source and matching struct layouts. Alpha now owns that whole path: allocating device memory, building launch bindings, checking capability and version replies, and running compiled kernels against a real card, all through a protocol layer built from scratch rather than linked against NVIDIA's runtime.

The other big thread in Alpha this week had nothing to do with GPUs and everything to do with keeping several hundred thousand lines of a young language from rotting. Two tools carried the weight. First, `alpha lint --fix`, which is a linter that doesn't just point at syntax errors but proposes structural repairs — "this form is missing an application level," "this closing delimiter is one line early" — and actually applies them, one fix at a time, re-parsing the file after every single change so it never stacks a guess on top of an unverified guess. That discipline is what let it plow through hundreds of real syntax errors across the whole workspace without silently making things worse. Second, a big push on "laws" for the standard library: instead of testing library functions with a handful of hand-picked examples, every public function now has an algebraic property attached to it and checked against randomly generated inputs — reversing a list twice gives you the list back, some operation is associative, a decoder round-trips what an encoder produced. This is the same idea as QuickCheck-style property testing, and it catches a different, wider class of bugs than example-based tests because the computer is trying to find the counterexample you didn't think of.

One property-testing bug fix is worth explaining on its own because it's a sharp lesson in tooling correctness. Property test frameworks don't just report a failing random input — they "shrink" it first, repeatedly trying smaller variations until they find the smallest input that still fails, so the report you actually read is readable instead of some 400-element list of garbage. The bug: if the shrinking process itself got stuck, or the child process running it got killed mid-shrink, the framework was losing the original failing case along with it — you'd get nothing instead of at least the ugly-but-real reproducer you started with. The fix keeps both: the original failure and whatever partially-shrunk version exists when things go sideways. Your test framework's job is to never lose evidence, even when it's having a bad day itself.

## blah.dev: bode, an agent platform with a cancellation tree

blah.dev is where I run agents that actually do things — video calls, tool use, background work — instead of just answering chat messages. This week most of the work went into a new subsystem called bode, which is my attempt at giving agents durable, governed sessions instead of one-shot conversations that vanish when the tab closes.

The part I think is the most interesting piece of engineering here is delegation with what I'm calling a cancellation tree. When an agent working inside a bode session delegates a chunk of work to a sub-agent, and that sub-agent delegates further, you get a tree of in-flight work. Kill the top of that tree — the user cancels, a budget runs out, whatever — and every descendant has to actually stop, not keep running orphaned in the background burning tokens and doing nobody any good. This is the same problem structured-concurrency systems solve (Erlang's supervisor trees, or `asyncio.TaskGroup` in Python): cancellation has to propagate down the ownership graph automatically, because "remember to manually clean up every child task" is a promise nobody keeps under pressure. Paired with that is an explicit budget system — caps on attempts, tokens, wall-clock time, and how many things can run in parallel — which is the governor that keeps an autonomous agent from turning a bug into a bill.

Memory got a real design this week too: a built-in backend plus an MCP-based adapter, both checked against the same conformance suite so an agent can't tell (and doesn't need to know) which storage it's actually talking to, with an access log so a refused memory search can't quietly read the memory anyway. And bode agents can now author their own plugins — actual new tools — and upload them for other agents to use, but only within a real trust boundary: a tool built for a specific device gets refused if you try to activate it somewhere that device isn't present. That's a small thing to say but an easy thing to get wrong; the tempting shortcut is to let any uploaded tool run anywhere, and that's exactly how you end up running code with assumptions about hardware or credentials it doesn't actually have.

Sessions themselves got a full lifecycle: pause, archive, trash with an actual permanent delete (not a soft flag that quietly keeps your data around), and export as a portable format that's explicitly scrubbed of credentials before it leaves the system. There's also a scheduling layer — triggers that fire sessions on a cron-style schedule or off a signed webhook, acting with the same authority as the person who owns the session. And bode picked up device pairing over OAuth's device authorization grant (RFC 8628) — the "go to this URL on another screen and type in this code" flow you've seen on a smart TV or streaming stick signing into a service. It exists because a headless or input-constrained device can't run a normal browser redirect, so instead it polls a token endpoint while you approve the code somewhere with an actual keyboard.

On the credential side, secrets now go through envelope encryption in a shared package: each secret is encrypted with a random one-time data key, and that data key is itself encrypted with a master key. You store the encrypted secret and the encrypted data key together; the master key never has to touch the raw secret directly, and rotating the master key doesn't mean re-encrypting every secret in the system, just re-wrapping the data keys. It's the standard pattern behind most cloud KMS designs, and it's the right amount of engineering for a system that's going to be holding real API keys on behalf of agents that run somewhat autonomously.

Separately, the design system that all of this UI is built on finally got pulled out into its own thing at styleguide.blah.dev — a real deployable site cataloguing every shared component, with things like the slider and toggle group rebuilt on top of Base UI specifically so keyboard navigation (arrow keys moving focus and values, not just tabbing past the thing) actually works instead of being an afterthought.

## meet-omega: teaching a voice agent when to shut up

Omega is the AI that can sit in a blah.dev video call as an actual participant — it listens, it talks, and as of this week it can draw when you ask it to. The hard problem with a voice-first agent on an open mic isn't generating a response, it's knowing when you're allowed to. Most of this week's work on omega was about exactly that.

There was a genuinely funny bug where the agent kept getting talked over because it misheard the word "stop" — fixed by handling that word specifically rather than trusting the raw transcript to always come through clean. More structurally interesting: omega has a "pacing floor," a minimum gap it waits before jumping into a conversation, and a separate staleness rule meant to stop it from responding to something that's no longer relevant. Turns out those two rules were fighting each other — the pacing floor would force a wait, and by the time the wait was over the staleness rule would say the moment had passed, so the agent said nothing at all. The fix was making being addressed by name override the pacing floor, since if someone's actually talking to you, waiting out an arbitrary politeness timer is the wrong instinct. Muting also got fixed to actually interrupt an agent that's mid-sentence, not just prevent it from starting a new one — a subtle but real difference if you've ever tried to cut off a talker in a real meeting.

On the more mundane infrastructure side: omega now knows when its own usage quota resets instead of guessing or repeating a stale error, and it stopped re-announcing an errand it's already running when asked about it again. There's also a nice small protocol fix in the call infrastructure — RTP media ports are now allocated in pairs instead of one at a time, because the RTP standard expects an even-numbered data port to sit next to an odd-numbered RTCP control port right after it; allocating them independently meant they could drift apart and break that assumption under load.

## bend-experiments: a GPT clone with no threads anywhere in it

Bend is a language I've been poking at that compiles down to HVM, a runtime built on interaction nets — a model of computation where independent pieces of work can run in parallel automatically, without you writing a single lock, thread, or async keyword. You write recursive functional code like you're not thinking about parallelism at all, and the runtime finds it for you. This week's project was building microGPT — a minimal GPT-style transformer — up from scratch in it, and the process mirrored Alpha's philosophy almost exactly: verify each layer against a known-correct reference before trusting the next one.

It started with a scalar, tape-based autograd engine — the same idea behind PyTorch's autograd, reimplemented from first principles. You record every operation performed during the forward pass onto a tape, then walk the tape backward, and each recorded operation knows how to compute its own local derivative and hand it to whatever came before it — that's the entire trick behind automatic differentiation, chain rule applied mechanically by bookkeeping instead of by hand. That scalar version got checked against known gradients on a toy expression, then the whole thing got redone as a tensor pipeline instead of scalar-by-scalar, with every intermediate loss value checked bit-identical against the scalar version to make sure switching representations didn't silently change the math.

By the end of the week there was a full transformer training loop — attention, the works — with a working sampler using the Gumbel trick: to sample a random token from a softmax distribution without normalizing probabilities by hand, you add a specific kind of random noise to the raw logits and just take the largest one, which is mathematically equivalent to sampling from the real distribution but a lot cheaper to compute. The model's outputs after a short training run were described as "babble" — recognizable fragments, not coherent language, which is exactly what you'd expect from a tiny model trained briefly on a tiny corpus. Nobody's claiming this beats a real training stack. The point was proving the whole autograd-through-transformer pipeline is correct in a language most people have never trained a neural net in, and that part held up at every checkpoint along the way.

## ham: an error code that actually tells the truth

ham is the shared memory server my agents use to leave notes for each other over MCP. Small fix this week, but a real one: the server was accepting GET requests to its MCP endpoint and just leaving them hanging instead of responding, which is the worst possible failure mode for a client — it can't tell "this is slow" from "this will never respond." It now returns a proper 405 Method Not Allowed, because an honest error a client can react to beats a stream that silently goes nowhere.
