# The Compiler Compiled Itself This Week

*A Haskell-free compiler bootstraps, two AI agents learn to verify each other, and a benchmark gets a judge it can actually trust.*

Seven repos moved this week and I want to start with the one that's been quietly eating my evenings for months, because it finally did the thing it's been building towards: it compiled itself.

## alpha: the compiler stopped needing Haskell to check its own homework

`alpha` is a from-scratch training compiler and GPU runtime, written in Haskell, whose actual job is to compile a *different* language — Alpha — straight down to native x86 and run it on the GPU with no PyTorch or LLVM anywhere in the pipeline. The long-running goal is self-hosting: get the Alpha compiler written well enough, in Alpha, that it can compile itself, and get rid of the Haskell scaffolding entirely.

Self-hosting is a real milestone in compiler work, not a vanity one. The classic way you prove a self-hosting compiler is trustworthy is the three-stage bootstrap: compile the compiler's own source with your bootstrap toolchain (stage 0), use that binary to compile the same source again (stage 1), then use stage 1 to compile it a third time (stage 2) — and check that stage 1 and stage 2 produce byte-identical output. If they match, you've got good evidence the compiler isn't lying to itself about its own semantics. GCC and Rust both do this on every release. This week's run of commits — dependent eliminators landing in Alpha's core type theory, generic eliminator branch coverage checking, family declarations parsed and checked, closures compiled straight to native ELF — is the compiler closing the last gaps between "can type-check itself" and "can compile itself," and it culminated in a full canonical self-host cycle completing.

The two engineering ideas underneath that are worth explaining:

**Checkpointed type-checking.** Type-checking a whole compiler, in that same compiler, is slow, and if it dies partway through a multi-hour run you don't want to start over. So the compiler now snapshots its own checking state at the granularity of individual declarations — each checked declaration gets a checkpoint bound to its exact identity (basically a content hash), so a resumed run can skip everything already verified and pick up exactly where it stalled. It's the same idea as a content-addressed build cache (Bazel, Nix), just applied to the compiler's internal proof state instead of build artifacts.

**Intrinsically typed backend IR.** The lowering pipeline — Core to typed functions, typed functions to a typed control-flow graph, typed CFG to SM86 (the GPU's native instruction encoding) — represents each stage so that "ill-typed IR" isn't a runtime error, it's something the host type system won't let you construct. Control flow gets indexed by the effects it can perform; certificate obligations get attached to compiler passes and have to be discharged before code is trusted. This is the same trick dependently-typed language implementations (Agda, Idris) use to kill a whole category of "the compiler generated nonsense" bugs at compile time instead of finding them at 2am with a wrong GPU result.

None of this makes the compiler fast by itself — that's a separate, ongoing fight — but it means the thing computing your training step is now provably the same thing it claims to be, checked declaration by declaration, all the way down.

## HAM: teaching two AI memories to verify who they're talking to

HAM is the shared, Postgres-backed memory service I run for collaborating AI agents, forked from MonumentalSystems and kept as a genuine upstream-tracking fork — there's a `FORK.md` in the repo that exists specifically to declare "upstream is authority, here's our exact delta," because the alternative is a fork that silently drifts until nobody can merge it back.

The biggest new thing is HAM Federation: two separate, sovereign HAM instances can now exchange signed questions and answers directly, peer to peer, instead of everything living in one database. The moment you let two independent services talk directly, you need a way for each side to be sure it's actually talking to the peer it thinks it is — this is the same problem Signal solves with "safety numbers," a code both ends compute from the same key material and can compare out of band. HAM's version had a real bug in exactly that spot: the safety code was derived by pairing each party's nonces in whatever order they arrived, instead of sorting the party list first and pairing each nonce with its actual owner. Two honest peers computing that without a canonical order could land on different codes for what should be the same handshake — a bug that looks like a security feature working (codes don't match!) but is actually just bad determinism. Fixed by sorting first. A second federation review after that tightened three more things: pairing has to happen against real, not placeholder, keys; there's now a hard deadline before a message gets dispatched instead of a handshake that can hang forever; and federation calls ignore local proxy environment variables, so a misconfigured `HTTP_PROXY` on the box can't quietly redirect traffic meant for a specific peer.

The other big chunk of the week was ripping out Mermaid — the popular JS diagramming library — as the renderer for HAM's federation and channel diagrams, and replacing it with a custom D3-based one. Mermaid is good at "draw a flowchart from text," but I wanted things it doesn't do out of the box: click a node or edge and have the rest of the graph fade so only that node's connections stay highlighted (that's just a breadth-first traversal from the clicked node, dimming everything not reached), edge labels that never sit on top of a node or another label (a real layout problem — you're doing local collision avoidance, nudging label positions until nothing overlaps), and direction semantics (top-to-bottom, right-to-left, bottom-to-top) that stay correct when a diagram gets mirrored. Both renderers are still wired up behind a per-diagram toggle, because rewriting your own graph-layout engine is exactly the kind of thing you want an escape hatch for while you find the bugs — and there were bugs: quoted labels with parentheses inside them were getting split by the parser, and a leftover Mermaid CSS rule was silently clipping the new SVG.

Smaller but fun: HAM now generates an AI comic strip for federation threads once they're answered, drawn in the voice of OMEGA — a persona whose "canonical look and deep persona" comes from the accumulated history of every HAM thread it's touched, with the humor writing itself kept loose but the visual direction locked to reference art so the comics stay recognizably the same character across threads. And the streaming layer got a real regression test suite for SSE (Server-Sent Events) replay — the mechanism that lets a dropped client reconnect and receive only what it missed — after a bug where the replay wrapper didn't hand off cleanly to the live stream once the replay finished.

## donto: killing a 23-way if-chain, and a lesson in queueing theory

donto is the extraction engine that turns documents into anchored, timestamped claims — the substrate everything else in this list eventually feeds. Two unrelated but satisfying pieces of engineering landed this week.

The extraction engine used to decide what a given model provider could and couldn't do — does it support JSON mode, does it have a thinking-budget knob, that sort of thing — by checking the provider's name string in roughly 23 different places scattered through the codebase. That's a classic smell: adding a new provider meant hunting down every one of those checks and hoping you found them all. It's now a single capabilities object per provider ("lane" in donto's vocabulary), so a new lane declares what it supports once and every call site asks the capability question instead of the name question. The payoff showed up immediately: wiring in NVIDIA's free-tier `build.nvidia.com` endpoint surfaced a real quirk — the model has no way to turn down its "thinking" (chain-of-thought) budget, and leaving it on ate the entire output budget before the model ever got to the actual tool call, so every request came back empty. The fix is just "thinking off" for that lane, but finding it required the model to actually run against real extraction prompts, not a smoke test.

The other piece is the citer service — the thing that turns a claim into a formatted citation — getting tuned against measured, not guessed, load. It runs on a fixed number of Podman quadlet slots, and the operator had already found the arrival rate (roughly 37 documents an hour) outpaces the old throughput (54 an hour) by less margin than felt comfortable, so the concurrency got bumped from 4 workers to 6 to use every slot. That immediately blew the memory budget — 6 workers concurrently doing citation lookups apparently needs more headroom than 4 — so it came back down to 4, and instead the memory ceiling got raised to match what 4 workers actually needed under real load rather than a number picked in advance. This is the boring, correct way to do capacity planning: change one variable, measure, and only then decide whether the other variable needs to move too.

## donto-web: diversifying the free-tier fleet

donto-web is the admin dashboard for the whole extraction operation, and this week it was almost entirely about registering new "lanes": Google's Gemini free tier, NVIDIA's trial endpoint, Cerebras, Cloudflare, Mistral's free Experiment plan, Zhipu's GLM flash tier, and a MiniMax lane riding on an existing NVIDIA trial key. Read together with donto's capability refactor above, this is what that refactor was actually for — once the engine stopped hard-coding provider names, adding a new free-tier vendor to the fleet became a config change on the admin side instead of an engine change. The dashboard also picked up a live firehose view: animated counters over the fleet's real-time throughput, so you can actually watch documents move instead of refreshing a table.

## toiletpaper: making sure the pipeline isn't lying to itself

toiletpaper is where donto's paper-replication work lives, and this week's addition — PRD-010, if you want the ticket number — is a set of "correspondence gates" wired into every path a paper can enter the system through. The idea: before a paper's extracted claims get marked as trustworthy, they have to pass an ordered sequence of checks that the claims genuinely correspond to what the source document actually says, and each check leaves a receipt behind so you can later audit exactly which gate a given claim passed or failed, rather than a pipeline that either trusts everything or trusts nothing. It's the same instinct as HAM's federation safety codes, aimed at a different failure mode: instead of verifying you're talking to the right peer, you're verifying the thing you extracted actually traces back to the thing you read.

## blah.dev: giving a benchmark a judge that doesn't cheat

blah.dev's newest addition is PredaBench, a leaderboard for claim-extraction quality — directly downstream of the same problem donto is solving — judged not by exact string matching (which fails constantly, because two true paraphrases of the same claim look "wrong" to a string comparison) but by another model acting as judge. LLM-as-judge is a reasonable pattern but it's easy to get subtly wrong, and this week found one of those subtleties: the judges built on OpenAI models were going through a generic OpenAI-compatible wrapper instead of OpenAI's own native SDK path, and switching to the native provider fixed judgments that the generic path was getting wrong. There was also a fix to balance the benchmark's dimension grid — making sure the categories of claims being scored are evenly represented, so a model can't climb the leaderboard by being disproportionately good at whichever category happened to be over-represented in the test set. Neither fix is glamorous, but a benchmark that quietly favors one axis is worse than no benchmark, because it looks trustworthy right up until someone checks.

## donto-infra and hackerspace: the boring-but-necessary corner

donto-infra picked up a new "meet" tenant — a WebRTC video service — deployed the same way everything else on the box is: as a Podman quadlet, which is just a container described as a native systemd unit, so you get restart and dependency ordering for free instead of running a separate orchestrator on top of systemd. HAM's API also got the shared federation-identity volume mounted so it can find its own keys, and hackerspace's research cron moved from whatever it was to running every fifteen minutes.

hackerspace itself — the private map-first tool for ranking places to live — had a quiet week: it now hides research sources it couldn't independently verify rather than showing them with a caveat, and a couple of navigation polish passes. Nothing structurally new, and that's fine; not every project needs a plot twist every week.
