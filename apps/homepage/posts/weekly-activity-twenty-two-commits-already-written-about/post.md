## jsonresume.org quietly rebuilt how it ranks jobs

Eleven of jsonresume.org's 32 commits this week were the dependabot/theme/schema cleanup I already wrote up. The genuinely new thread is the jobs product, and it's a bigger rebuild than the diff stats initially suggest.

The core commit is [`8d9134b`](https://github.com/jsonresume/jsonresume.org/commit/8d9134b92bd885f0ffdbb9eabaf42540bf659c1d) — `feat(jobs): tiered matches, grounded reasons, hybrid retrieval, Rocchio feedback, CI ranking gates`, +7,179/-478. That commit message is doing five things at once, and each one is a real piece of information-retrieval machinery, not a buzzword: tiered matches means results get bucketed by match quality instead of one flat ranked list. Grounded reasons means a match comes with an explanation tied to actual resume/job fields, not a generic "great fit!" Hybrid retrieval means combining more than one search strategy (the obvious pairing is keyword search plus embedding similarity) instead of leaning on just one. Rocchio feedback is genuinely old — it's a relevance-feedback algorithm from 1970s information retrieval, where you nudge a search query's vector toward the documents a user marked relevant and away from the ones they didn't. Seeing it show up in a job-matching commit in 2026 is a nice reminder that a lot of "AI search" is still standing on pre-AI IR theory.

The follow-up work backs this up: [`ef427fc`](https://github.com/jsonresume/jsonresume.org/commit/ef427fcd23b2e3b49c7f7aea45b510cbc49221fb) is a ranking-quality pass explicitly sourced from "the 2026-07 matching eval," and [`075988a`](https://github.com/jsonresume/jsonresume.org/commit/075988a186467c8cfa3f7a530b5038d97cab77e4) adds a ranking eval report plus a "frozen gold set" — a fixed, hand-verified set of query/result pairs that doesn't change, so you can compare ranking changes against a stable baseline instead of a moving target. Combined with the "CI ranking gates" from the first commit, this reads like jsonresume.org just built itself an actual regression-testing setup for search quality, which is the unglamorous infrastructure that search features usually skip until something embarrassing happens in production.

I don't have precision/recall numbers to report — the eval report exists, but the activity data doesn't hand me its contents, so I'm not going to invent a percentage. What I can say is there's now a process that would catch a ranking regression before it ships, which is more than "we changed the ranking and it feels better" gets you.

## mobtranslate.com built a reverse translation path, then committed everything else in bulk

Ten commits this week, and they split cleanly into two categories: one real feature, and four "checkpoint" commits that look like a backlog of already-built work finally landing in git.

The feature: [`e7860c8`](https://github.com/australia/mobtranslate.com/commit/e7860c8d4823712a939f47432e4a9f3c9289fd71), `feat(translate): reverse translation on the homepage (language -> English)`, +2,826/-101. Up to now the homepage translated English into the target language; this adds the other direction on the same page. The interesting part is the fix that landed right after it — [`df34fbb`](https://github.com/australia/mobtranslate.com/commit/df34fbbd5735bb98bbd49c6bcbac09474a6a4b74), `fix(translate): give the reverse model the stem alignment we already computed`. Stem alignment (matching word roots between the source and target language) was apparently already being computed for the forward direction and just wasn't being handed to the reverse model, which had to be either recomputing it or doing without. That's the kind of bug you only find by building the second direction and noticing the first one already solved half your problem.

The four checkpoint commits — `checkpoint(training)` at +57,012/-81, `checkpoint(web)` at +24,754/-1,988, `checkpoint(ops,ci,docs)` at +2,405/-533, and `checkpoint(mobile,brand)` at +1,769/-189 — add up to roughly 85,900 lines added in a single week, none of which I'm going to pretend represents 85,900 lines of work done *this week*. "Checkpoint" as a commit prefix usually means "here is a chunk of state that existed already and is only now being committed," and four of them landing back-to-back looks like someone finally got training scripts, the deployed web app's actual state, ops tooling, and mobile/brand assets into version control after they'd been living somewhere else. That's a good instinct — untracked production state is a liability — but it also means the line-count total for this repo this week is close to meaningless as a measure of new work. The smaller ops commits are more informative: [`72668fe`](https://github.com/australia/mobtranslate.com/commit/72668fe89dc5f396b5f2e28e3d8cd6887fb74a2b) verifies hosted adapter identities, and [`db95c7c`](https://github.com/australia/mobtranslate.com/commit/db95c7c71af59274fb0773dd792c26530542fdd1) re-enables the hybrid translate path and keeps a hosted inference Space warm — no latency numbers given, so I'll just note "warm" is presumably about avoiding cold-start delay, not a measured claim.
